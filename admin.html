🔒Architecture: Browser → /api/* Cloudflare Edge Functions → Supabase (service_role, server-only) + GitHub (token, server-only). Browser receives only a short-lived JWT in memory. Zero secrets in code or localStorage.

Step 1 — Supabase: Create Project & Run SQL

supabase.com →
  1. Go to supabase.com → Sign up free → New project → choose any region → Free plan → wait ~2 minutes
  2. Settings → API → copy two values: Project URL and the service_role key (the second key — NOT the anon/public key)
  3. SQL Editor → New query → paste the entire contents of supabase-setup.sql → click Run
  4. Verify: the output table should show 12 rows, all with rls_enabled = true

Step 2 — Generate Your Password Hash

Computed locally via Web Crypto API — never transmitted. Only the hash goes into Cloudflare.

Hash appears here as you type...
This 64-character hex string goes into Cloudflare as ADMIN_PASSWORD_HASH.

Step 3 — Generate JWT Secret

Cryptographically random 80-char string. Generated locally — never sent anywhere until you paste it into Cloudflare.

Step 4 — Cloudflare Environment Variables

Cloudflare →

Pages → hmg-academy → Settings → Environment variables → Add variable — set all 8 for both Production and Preview:

SUPABASE_URL = https://YOUR_PROJECT_REF.supabase.co
SUPABASE_SERVICE_KEY = eyJhbGci... (service_role — NOT anon)
JWT_SECRET = (paste from Step 3)
ADMIN_PASSWORD_HASH = (paste from Step 2)
GITHUB_TOKEN = github_pat_... (repo contents read+write)
GITHUB_USER = cssadewale
GITHUB_REPO = hmg-academy
GITHUB_BRANCH = main
⚠️Never commit these to GitHub. They live only in the Cloudflare dashboard. Edge functions read them via env.VARIABLE_NAME.

Step 5 — GitHub Fine-Grained Token

GitHub Tokens →
  1. GitHub → avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
  2. Name: HMG Academy Deploy · Expiration: 1 year
  3. Repository access → Only selected → hmg-academy
  4. Permissions → Repository permissions → Contents → Read and write (everything else stays No access)
  5. Generate token → copy immediately (shown once) → paste as GITHUB_TOKEN in Cloudflare

Step 6 — Repo Structure & Push to GitHub

Your GitHub repo must have this exact folder structure. The functions/api/ folder is what Cloudflare detects to deploy edge functions automatically — no extra config needed.

hmg-academy/               ← GitHub repo root
├── admin.html
├── index.html
├── about.html
├── services.html
├── tools.html
├── notes.html
├── register.html
├── contact.html
├── 404.html
├── supabase-setup.sql     ← safe to keep, has no secrets
├── functions/
│   └── api/
│       ├── _middleware.js ← JWT verify + Supabase helper
│       ├── login.js       ← POST /api/login
│       ├── data.js        ← All CMS operations
│       ├── deploy.js      ← POST /api/deploy
│       └── health.js      ← GET /api/health
└── _shared.css, _shared.js, assets/ ...

After placing all files, commit and push. Cloudflare Pages detects the push and rebuilds in ~45 seconds.

Step 7 — Verify the Deployment

Verification checklist:
✅ Login screen shows green "API Connected" badge
✅ /api/health returns ready: true with all env vars confirmed
✅ You can log in with your chosen password
✅ Dashboard loads live stats (notes, tools, etc.) from Supabase
✅ Add a test note → check Supabase Table Editor → note appears in hmg_admin_config.notes
✅ Deploy panel → select only robots.txt → Deploy → success in ~10s
✅ Audit Log → Load → shows your login event and deploy event

Common Errors & Fixes

❌ "Cannot reach /api/health" — red badge on login
The functions/ folder is not deployed. Check Cloudflare Pages → Deployments → build log for errors. Confirm the 5 .js files are in functions/api/ in your GitHub repo.
❌ /api/health shows any env var as false
That env var is missing or misspelled in Cloudflare. Cloudflare → Pages → Settings → Environment variables → check spelling and confirm it's set for Production (not just Preview).
❌ "Incorrect password" on login
ADMIN_PASSWORD_HASH doesn't match. Re-generate the hash in Step 2 above by typing your exact password. The hash is case-sensitive — copy it exactly (64 hex chars, no spaces).
❌ Deploy fails with GitHub 401 or 404
Token expired or wrong permissions. Generate a new fine-grained token (Step 5). Confirm GITHUB_REPO matches your exact repo name — it's case-sensitive.
❌ Data not loading after login
Supabase RLS is blocking the anon key. Confirm you used the service_role key in SUPABASE_SERVICE_KEY. Also confirm you ran the full supabase-setup.sql — all 12 tables with rls_enabled = true.
❌ "Too many failed attempts" lockout
Intentional security. Wait 15 minutes. If you forgot your password, generate a new hash in Step 2, update ADMIN_PASSWORD_HASH in Cloudflare, save, and redeploy.
